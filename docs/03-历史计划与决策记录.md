## 二、立项原案：《AIKernel_AI重构计划》（2026-08 初版，全文要点）

**总体目标**：在 Linux 6.18.39 全部核心子系统系统性地埋入 AI 控制函数（Hook/Callout），每个子系统都有 AI 可介入的决策点，AI Runtime 作为中枢统一调度。

**核心模式**（每个子系统统一三层埋点）：
- **Hook 层**：内核执行路径关键决策点插入 `ai_*_hook()`（条件编译，无 AI 时零开销）；
- **Telemetry 层**：关键数据变动处 `ai_telemetry_*()` 采集特征送入模型；
- **Policy 层**：推理结果经 `ai_policy_*()` 回调影响内核行为。

**配置体系**：`CONFIG_AIKERNEL` 总开关 + 每子系统独立开关（全 default n；n 时 static inline 空函数编译器消除）。

**模型部署四模式**：内嵌 TinyML（实时决策）/ 用户态下发（复杂模型，sysfs/netlink 下发内核只做推理执行）/ BPF 协同（BPF 程序作推理载体）/ 硬件卸载（NPU/GPU）。→ 实际演进：用户态下发模式落地为 AIKWMDL v1 + Q31 定点 MLP（内核禁 SSE 不能用 float），TinyML/BPF 协同保留为架构预留。

**关键设计决策**（立项期定，全程有效）：
1. 零回归：n 配置行为一致，每模块合并前过相关 selftest；
2. 安全边界：模型权重不可普通用户修改；model_load 需 CAP_SYS_ADMIN（LSM 保护）；决策日志非特权不可读；BPF AI helper 受验证器限制；
3. 性能假设：AI Hook <5µs（内嵌）/<50µs（用户态）；遥测记录 <100ns；sysfs/procfs "一个文件一个值"；
4. 内核 AIKernel/ 目录框架：core/sched/mm/io/net/security/power/vfs/interrupt/lock/time/virt/bpf/tools/test/docs（+rag 后加）。

## 三、B 轨原案：《数据源与日志系统计划》v2.0 要点

**理念**：这不是日志系统，是"AI 的感官神经系统"——AI 看事件→决策→执行→观察结果→全部记录为训练样本。核心原则：全量原始数据（不脱敏不哈希）、因果闭环、实时（ring buffer）+离线（Parquet）、覆盖所有子系统、可控制（Policy 直改内核行为）。

**17 大类 ~101 子类分类体系**（B 轨骨架，实际落地 18 大类 ~104 子类——第 18 类为 AI 自我观测 AI_DECISION/AI_OUTCOME）：

| 类 | 名称 | 子类 | 类 | 名称 | 子类 |
|----|------|------|----|------|------|
| 1 | CPU 与调度 | 8 | 10 | 锁竞争与同步 | 4 |
| 2 | 内存管理 | 10（含 OOM/KASAN"训练金矿"） | 11 | 时间与定时器 | 4 |
| 3 | I/O 与存储 | 6 | 12 | 电源管理 | 5 |
| 4 | 网络 | 10（payload 按采样零脱敏） | 13 | 虚拟化 | 5 |
| 5 | 用户输入 | 5（tty/键鼠/touch/syscall/exec 全量） | 14 | BPF/Tracing/Perf | 4 |
| 6 | 进程与线程 | 7 | 15 | 用户行为 | 6（会话/应用/活动/模式/GPU） |
| 7 | 文件系统 | 6（全量路径零截断） | 16 | 硬件与驱动 | 5（MCE/NMI/device/dma/platform） |
| 8 | 安全事件 | 8（LSM/seccomp/cap/audit/key/crypto/内存安全检测/加固违规） | 17 | 内核构建与配置 | 3（kconfig/module/sysctl） |
| 9 | 中断与异常 | 5 | | | |

**数据格式定稿**：遥测记录 = 23B packed 定长头（timestamp_ns/pid/tgid/cpu/category/event_type/severity/data_len）+ ≤4096B 原始数据；决策记录 ai_decision_record = 4 时间戳 + decision_data[8] + outcome(0未知/1成功/2部分/3失败/4恶化) + metric_delta + model_version/confidence + 扩展（decision_id/domain/source/executed/safety_clamped）；离线 Parquet 按天/按类别落 `/var/lib/aikernel/`（schema 固定见 aikd/README.md）。

**三层采集架构**：感知层（per-CPU 128KB ring，<100ns）→ 思考层（特征提取→推理→策略匹配）→ 执行+存储层（/proc/ai/ 实时 + NETLINK_AI 指令 + aikd Parquet + RAG 增量）。

## 五、Prompt 00~15 设计要点与关键决策（原 Design 00~16 摘要）

### Prompt 00（前置）
- **现状盘点**（08-03 起点）：agent/ai 全部为用户态程序（shell/runtime/provider/cloud/config + 内核侧仅 /proc/aikernel 静态页）；全树零 `ai_telemetry_*`；17 大类感知 0 覆盖。
- **基线报告**：WSL2 + gcc 13.3.0 + 6.18.39；vmlinux 52,272,448B / bzImage 14,132,224B / 0 警告；性能工具（hackbench/fio/iperf3/cyclictest）基线缺失（后续以 QEMU 静态二进制补齐）。
- **决策 #1（符号冲突消解）**：agent 侧 `CONFIG_AIKERNEL` 改名 `CONFIG_AIKERNEL_AGENT`（方案 b），为内核侧总开关让出符号名。
- **决策 #2（零回归核对方法）**：非 git 仓库 → 文件时间戳 + find + vmlinux 大小对比 + 预处理产物（.i）抽查 ai_ 引用 = 0。

### Prompt 01（AI Runtime 核心与遥测框架）
- per-CPU 128KB 无锁 ring buffer：单写 head（smp_store_release）/读者 tail（atomic cmpxchg）；满则丢弃 +dropped（绝不阻塞不覆盖）；写路径 ktime+采样+两段回绕 memcpy，预算 <100ns；
- 17 大类 101 子类事件枚举 + 101 个 static inline 包装占位；
- 64 槽策略注册表骨架、16 槽模型注册表、8 槽回调表；
- 内核侧错误码追加 BUSY/RING_FULL/DISABLED。

### Prompt 02（用户态接口层与感知出口）
- 三出口一次打通：/sys/kernel/ai/ 控制面（kobject）、/proc/ai/ 状态面+telemetry 流出口（raw/human 双模式）、NETLINK_AI 协议族；
- **决策 #3（NETLINK 编号）**：设计稿曾写 32，实现时定为 **31**（23~31 保留区，<MAX_LINKS=32）；Kconfig 注释后已同步修正；
- **决策 #4（运行时开关语义）**：ai.enabled=0 启动 → 节点全部不创建（等价原生内核）；运行时写 0 → 节点在但操作拒绝（AI_ERR_DISABLED）；
- init/main.c 接入仅 3 行条件编译（kcsan_init 后 rest_init 前）；initramfs 模型预加载钩子；
- ai.cgroup 骨架：SUBSYS(ai) 挂 cgroup_subsys.h（计数 14→15 <16）。

### Prompt 03（调度）
- 统一头模式确立：`AIKernel/<sub>/<sub>.h`（Hook 原型+payload+stub）+ 上游文件条件 include + 调用点条件块 → n 配置预处理产物与基线逐字节一致（**零回归由构造保证**，后续全部子系统复制此模式）；
- 8 处 sched 埋点：__schedule/context_switch/try_to_wake_up/wake_up_new_task/enqueue/dequeue/migration/sched_balance_rq（6.18 已从 load_balance 改名）+ pelt/rt/dl/ext/isolation/syscalls/psi；
- 每秒采样器模式（kthread，cpu_load/utilization/frequency/cstate/temperature/rq_depth/psi）；
- 进程分类启发式：util_avg≥512→AI_LOAD；≤256 且 pcount>100→INTERACTIVE；否则 BATCH。

### Prompt 04（内存）
- 9 Hook（fault/readahead/reclaim/workingset/alloc/thp/ksm/oom/cma）+ 33 个发射辅助；
- **决策 #5（采样机制定型）**：`sample_take()` 前置判定 + `emit_direct()` 直写分离（修复双重采样 bug）；CRITICAL 事件（OOM/KASAN）ring 满时逐出最旧不丢；
- 默认采样率：page_alloc 1/32、slab 1/64、filemap_read 1/16、page_fault 全量、缺页延迟 1/16；
- **6.18 适配**：khugepaged_scan_mm_slot 在 khugepaged.c（非 huge_memory.c）；do_shrink_slab 在 shrinker.c（已拆分）；struct scan_control 为 vmscan.c 私有 → Hook 传标量；
- KASAN/KFENCE 报告"打印前发射"（训练金矿全量入 ring）。

### Prompt 05（I/O）
- 块层 5 Hook + 自研 I/O 调度器 `ai`（注册名 ai，简化 deadline 语义族：读优先+期限 rb 树+fifo；`echo ai > /sys/block/*/queue/scheduler` 显式启用，n 配置不注册零回归）；
- **决策 #6（字符设备读写归属）**：fs/char_dev.c 只有 open；read/write 由代表性类（/dev/random + tty）落地，通用归口 VFS 层；
- **6.18 适配**：磁盘 IO 错误路径在 blk-mq.c blk_update_request（genhd.c 无错误路径）；bio issue_time_ns 需 CONFIG_BLK_CGROUP=y；
- 中断上下文安全：bio_endio/complete_request/mix_pool_bytes 全部无锁无分配不睡眠直写。

### Prompt 06（网络）
- 11 Hook + ai_cca 拥塞算法（reno 族 AIMD 底座 + cong_hook 咨询；`echo ai_cca > /proc/sys/net/ipv4/tcp_congestion_control` 显式启用）；
- **决策 #7（网络采样分级定稿）**：socket 生命周期/retransmit/abort/dns 等全量；rtt/cwnd 1/16；udp 1/64；ip 1/128；每包路径（nf/xdp/netdev/gro）1/256；**tcp_packet_raw payload 采样默认关**（模块参数 ai_net_payload_sampling 打开后 1/256，内容零脱敏）；
- HTTP/TLS 内容识别（8 方法+Host 头/状态码/ClientHello SNI+cipher 解析，越界检查）；
- **6.18 适配**（8 处）：xdp_do_redirect 在 filter.c；tcp_abort 在 tcp.c；CA 状态机在 tcp_cong.c；TC 数据路径在 sch_generic.c；conntrack bytes 需 ACCT（未开=0 如实记录）。

### Prompt 07（安全）
- **AI LSM（ID 114）可插拔**：DEFINE_LSM(ai) 默认不在 CONFIG_LSM 列表（运行时禁用零影响），`lsm=ai,...` 显式启用；3 个真挂接钩子 file_open/ptrace_access_check/task_kill + per-pid 行为模型表 256 槽（10s 滑动基线 + Z-score 异常分，默认 detect-only）；
- AI 审计模块：audit_log_end 原始字节零脱敏同步入 32KB ring + 攻击链关联表（64 槽×深度 8）；
- seccomp/cap/keys/crypto 4 个 ai_sec_* Hook；KASAN/KFENCE（Prompt 04 已埋）核对去重，kmsan/ubsan/kcsan/cfi/usercopy/stack_overflow 本步补齐；
- **决策 #8（payload 边界）**：全部安全事件 ≤233B（23B 头 + human 模式 256B chunk），路径 200B、seccomp insns 样本 ≤200B（268B 记录曾阻塞 human 流式读取）。

### Prompt 08（VFS）
- 9 Hook（dcache/inode/path/writeback/epoll/aio/dax/rw/exec_command）+ 24 事件；
- **决策 #9（零截断语义）**：路径 ≤1023 完整记录；≥1024 **整条丢弃 + path_overflow 计数**（丢弃≠截断）；
- **决策 #10（open/close 归口防双记）**：vfs_open()（fs/open.c，跳过 S_IFCHR）+ chrdev_open()（补记 /dev/xxx）分家；close 归口 __fput()（dput 前发射，kthread current->fs==NULL 防御）；
- per-file 读写字节表（256 槽哈希+atomic64 无锁）；热路径优化：每次查找仅 1 次 per-CPU inc_return + 1/32 采样（TCG 实测 find/ls -lR 零回归）；
- 顺带修复 dcache.c 死 include（lglock.h→memblock.h，6.18 无此头）。

### Prompt 09（中断/锁/时间三域合并）
- **决策 #11（延迟敏感区埋点铁律）**：一切 IRQ/软中断/NMI 边缘路径 = 原子写（emit_direct）+ per-CPU 预分配槽位（零运行时分配）+ 可重入（ktime IRQ 安全 + comm 直读）+ hook 内禁止加锁/睡眠/分配；

- spin 争用 1/256 采样；lockdep/watchdog 埋点随 CONFIG 扩展编译实编译验证。

## 八、过程教训（从 Design/Log/记忆沉淀，供后续开发避坑）

1. 跨 ssh heredoc 必挂——一律"本地写文件→scp→执行"；
2. QEMU TCG 计时仅供参考，性能结论以设计拆解+多次中位数为准；TCG 下 per-CPU 逐次累计会放大开销（热路径计数方案：每次 1 inc_return+分支）；
3. 早期启动（timekeeping_init 前）禁 ktime；per-CPU 计数器禁止对已偏移指针二次 __this_cpu_*；
4. 扩展配置构建（把 CONFIG 打开单独编译一遍）是验证"按配置不可编译文件"埋点的标准手段；
5. 测试残余纪律：临时模块树外构建、initramfs 测后还原、ring 清空、敏感遥测数据（凭证/密钥/审计）测试后必须清空；
6. 验收铁律：证据说话（dmesg/系统调用回读/mock 计数/md5），"模型说成功"不算数（1.5B 模型会幻觉报成功）；
7. 参数化 mock 换场景必须 fuser -k 端口清场（pkill+1s 不可靠）；
8. 验证一律用功能证据，不锚定 md5（并行线会重建镜像/二进制）。
