## 一、项目是什么

**AIKernel** 是在 Linux Kernel 6.18.39 之上构建的"AI 作为主体、内核作为被管理对象"的控制系统：在内核全部核心子系统中系统性地埋入 AI 感知点与决策点，让 AI（本地模型或云端 LLM）成为操作系统的"运行时大脑"——

- **能看**（全量零脱敏感知：17 大类 ~104 子类遥测，per-CPU ring buffer）；
- **能想**（推理决策：内核 ai_runtime_think 决策框架 + 用户态 agent 工具闭环）；
- **能做**（策略执行控制内核行为：ai_policy 策略引擎 + 可控参数表 + NETLINK_AI 下发）；
- **能学**（因果链 trigger→decision→outcome + RAG 知识库 + aikd Parquet 训练数据管道）。

核心理念 all-ai：AI 控制全部，感知数据全量、原始、零脱敏。同时保持 Linux 开放性——AI 只是系统里的一个程序，bash 永远在，一切 AI 功能默认关闭（CONFIG_AIKERNEL=n 时零回归）。

### 发行形态（2026-09-30 快照）

- 内核侧：bzImage 含 AIKernel/ 17 子目录，27 个可控参数（26 真实生效 + 1 诚实保留），NETLINK_AI(31) v2 定向下发，5 个已通电 AI 决策挂点（OOM 评分偏置 / vruntime 加权 / 唤醒抢占 / 预读 / 回收优先级，默认关、AI 经工具开启），模型下发真推理（Q31 定点 MLP），KUnit 37 用例。
- 用户态：aikernel-shell（C 静态链接）REPL + ask 工具闭环（74 工具注册表，五通道），W2 危险操作 y/N 再校验，本地/云端双通道真增量流式，会话持久化。
- ISO 安装盘（GRUB → 安装器 → 内置 Ollama + qwen2.5:1.5b，装完离线即用）。

## 二、总体架构：四层 + 两轨

### 2.1 四层架构（重构总纲 v3.0）

```
┌─────────────────────────────────────────────┐
│  Layer 4: RAG 知识大脑                       │
│  • 内核源码全文索引  • 接口文档  • 历史经验   │
│  • 项目文档  • 修改日志  • 决策因果链        │
│  → AI 能"记住"整个内核，随时检索相关知识      │
├─────────────────────────────────────────────┤
│  Layer 3: AI Runtime 中枢                   │
│  • 模型加载/推理  • 决策路由  • 策略执行      │
│  • 感知数据读取  • 因果链记录                │
├─────────────────────────────────────────────┤
│  Layer 2: 数据感知网络（Telemetry）           │
│  • 17 大类 ~101 子类  • 全量原始数据          │
│  • per-CPU ring buffer  • 零脱敏            │
├─────────────────────────────────────────────┤
│  Layer 1: 内核 Hook 埋点（Kernel Mods）      │
│  • 上游 166+ 文件最小侵入改造  • 15 个子系统  │
│  • 条件编译  • 零回归保证                     │
└─────────────────────────────────────────────┘
```

### 2.2 两条线的分工

| 线 | 位置 | 职责 |
|----|------|------|
| **内核侧**（A 轨埋点 + B 轨感知） | `AIKernel/`（core/sched/mm/io/net/security/power/vfs/interrupt/lock/time/virt/bpf/test 16 子目录，docs/ 与 tools/ 为空目录；用户态工具在内核树顶层 `tools/ai/`） | Hook 埋点、AI Runtime 中枢、遥测 ring buffer、策略引擎与安全边界、sysfs/procfs/netlink 出口 |（rag/ 已随 W7S 移除，SME 统一检索替代） |
| **用户态 AI 本体**（agent 线） | `agent/ai/`（shell/runtime/provider/cloud/local/config/memory/policy/tools 等） | AI Shell 交互、ask 工具闭环、Provider（云端 OpenAI Compatible + 本地 Ollama/OpenAI 兼容端点）、TOML 配置、aikd 训练数据管道 |

两条线通过函数调用接口对接（详见 `02-接口与指令集参考.md`）。

### 2.3 数据流主线

```
用户/事件 → agent（aikernel-shell ask 工具闭环 / chat）
   │ ①检索：RAG 知识库（faiss，语料 = 接口文档 + 内核源码 + 项目文档 + 历史）
   │ ②调用：五通道（NETLINK_AI / procfs / sysfs / exec / memory）
   ▼
内核侧 AIKernel/：ai_runtime_think() 决策框架 → ai_policy_execute() 策略引擎
   → 安全边界三件套（global_enable / max_impact_pct / 快照回滚）
   → 子系统 ai_*_hook() 决策点 / ai_control 参数 apply
   ▼
③感知回流 → ai_telemetry_*() 写 per-CPU ring buffer（<100ns）
   → /proc/ai/telemetry 或 NETLINK_AI SENSE 拉取 → aikd 按天落盘 Parquet
④因果链 → trigger→decision→outcome 全链记录 → /proc/ai/chains → 训练样本
```

### 2.4 开发铁律（全程有效）

1. **设计先行**：改任何内核代码前先写设计文档（原 AIKernel_Design 流程）；
2. **零回归**：所有埋点 `#ifdef CONFIG_AIKERNEL_XXX` 条件编译 + `static inline` 空函数兜底，`CONFIG_AIKERNEL=n` 时行为与原生完全一致（由构造保证）；
3. **全量零脱敏**（all-ai）：感知数据不哈希、不脱敏、不省略；路径超限整条丢弃并计数（丢弃≠截断）；
4. **接口必须登记**：新增接口必须登记（现登记于 `ARCHITECTURE.md` 与工具注册表 tools.json）；
5. **最小侵入**：上游文件只做条件 include + 访问器 + 挂接点，不物理拆分；
6. **最小批次**：每批 ≤15 个文件，每批独立验证（编译 0 警告 + 功能 + 性能）。

## 四、上游子系统覆盖现状

上游含 AIKernel 埋点引用的 `.c/.h` 文件实测 **166+** 个（随演进增长；ARCHITECTURE.md 有分域对照）：

- **已覆盖**：kernel/ 全域（sched/fork/exit/signal/futex/seccomp/locking/irq/time/power）、mm/ 核心、net/ 全栈 20 文件、fs/ 20 文件、block/ 6 文件、security/（LSM/seccomp/keys/commoncap）、drivers（input/tty/cpuidle/cpufreq/thermal/virtio/base）、arch/x86（syscall 采样/kvm/mce/nmi/kprobes/cfi）、crypto、kernel/bpf、kernel/trace、kernel/events、lib/ubsan、kernel/dma、kernel/module、fs/proc/proc_sysctl 等。
- **零埋点域**（规划后置）：drivers/gpu（DRM）、drivers/usb、drivers/media、sound、net/ipv6。
- **"能接就接"判定**：必须有决策空间、有状态可观测、有安全边界才接；纯硬件语义/数学不变量/热路径纳秒级处**不接**（例：时钟源读取路径、IDT 向量分发汇编、原子指令、RCU 宽限期状态机核心、printk 写入路径）。

## 五、AI 化三级蓝图（L1→L3）

- **L1 内核资源调度**（已基本完成）：可控参数 real 化、ai_cca、elevator `ai`、aiguard、AI LSM、NETLINK_AI v2 定向下发。剩余 reserved 参数逐波接真（net.qdisc 诚实保留——dev_graft_qdisc 实测会冻结 guest 网络栈）。
- **L2 系统服务与外设**（规划）：uinput 输入注入（CONFIG_INPUT_UINPUT=y 已备）、DRM/KMS 显示遥测与 ai_drm_commit_hook、网络 QoS（qdisc/nftables）、进程/服务管理（freeze/kill 走审计强制）。
- **L3 桌面/UI 层**（规划，三层配合）：内核 DRM atomic（管线编排）+ uinput（物理级输入注入）+ 用户态合成器协议（窗口/图标/表面，Wayland 私有 protocol 或 sway IPC/Mutter DBus）。关键认知：Linux 不允许直接写显存逐像素控制，像素合成在用户态 Mesa/合成器；AI 以普通会话进程身份连接合成器，跨会话操作被 Wayland 安全模型天然阻止。推进顺序：遥测（看见桌面）→ uinput 注入（能"动"）→ 合成器协议（能"布局"）→ DRM 编排（能"调管线"）。
