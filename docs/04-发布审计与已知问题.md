## A 类清单（发布 Blocker）

### A1. 云端 Provider 虚标流式能力（CAP_STREAM），stream 函数是桩
- **位置**：`agent/ai/cloud/provider_openai_compatible.c:299`（宣称）、`:241-250`（桩）
- **宣称**：`provider->capabilities = AI_PROVIDER_CAP_CHAT | AI_PROVIDER_CAP_STREAM;`
- **实际**：`openai_stream()` 五行全 `(void)` 忽略参数，`return AI_ERR_NOT_IMPLEMENTED;`。`capabilities` 字段全库无消费方；云端流式真实现本就在 `cloud_backend.c:161-179`（stream=1 且带 on_delta 时真发 SSE 并聚合增量）。
- **【处置 09-29 晚】已修复**：云端真增量流式落地（https_post_stream chunked 状态机，token 时间戳 199.7ms 跨度实证）；provider 层 stream 桩/死桩清除。

### A2. 启动横幅与 /proc/aikernel 输出硬编码假状态
- **位置**：`agent/ai/core/ai_core.c:24-26`、`agent/ai/shell/aikernel_main.c:53-56`
- **宣称**：两处无条件打印 `Cloud Provider : Ready`、`Local Provider : Offline`；实际是纯常量字符串，不读任何 provider 状态——未配 API key、断网时仍显示 Ready。
- **【处置 09-29 晚】已修复**（假状态消除）。

### A3. 48 工具旧版 tools.json 遗留，且加载优先级高于新版
- **位置**：旧表 `agent/ai/tools.json`（48 工具、version 1）；新表 `agent/ai/tools/tools.json`（69 工具、version 2）；加载逻辑 `tool_registry.c:588-638`（优先级：env → cwd `./tools.json` → cwd `tools/tools.json` → exe 同目录两处）。
- **事实**：在 `agent/ai/` 目录直接运行二进制时，cwd 优先级正好命中旧 48 工具文件，**静默加载旧注册表**（少 21 工具、无 v2 风险级/通道字段），无警告。
- **【处置 09-29 晚】已处置**（旧表移出搜索路径）；现役注册表为 74 工具（09-30 口径 73，W7S 扩至 74）。

### A4. agent 侧 3 个 Kconfig 开关零消费方：配置面与构建事实不符
- **位置**：`agent/ai/Kconfig:52-83`（AIKERNEL_CLOUD_PROVIDER / LOCAL_PROVIDER / STREAM_MODE）
- **事实**：全树对这三个 CONFIG 零 #ifdef 引用；用户态二进制由 Makefile 无条件编入全部源文件——`.config` 里 `is not set` 会让人误以为"没编进去"，实际开与不开产物完全相同。
- **【处置 09-29 晚】已修复**：三开关真接线（nm 矩阵验证 obj-$(CONFIG_...) 生效）；Kconfig 反向过时 help（C8）一并清理。

## B 类清单（功能缺口/质量问题）

### B1. Provider 层 local_stream 死桩（与真实现双轨并存）
- **位置**：`local/provider_local.c:122-133`（返回 NOT_IMPLEMENTED）、`:183`
- **事实**：本地流式真实现是 `local/local_stream.c`（149 行，Ollama NDJSON + OpenAI SSE 双协议），经 `local_backend.c:64-66` 接线；provider 层桩不可达。
- **【处置 09-29 晚】已清除**（死桩删除）。

### B2. 内核 model_load：任意 .bin 均按 echo 推理，无真实模型格式
- **位置**：`AIKernel/core/ai_startup.c:196-228`（真读文件）、`:145-165`（ai_echo_infer 回声）
- **事实**：加载通道（加载/卸载/注册表/权限）为真实现，但模型 ops 一律 ai_echo_ops——推理=回声。
- **【处置 09-29 晚】已修复**：model_load 真推理落地——AIKWMDL v1 格式 + Q31 定点 MLP（内核禁 SSE 不能用 float），echo-ops 彻底删除，`/sys/kernel/ai/model_infer` + `model_out` 推理面，对照 bit-exact。踩坑记录：6.18 `kernel_read_file_from_path` 语义 = buf_size 必须覆盖文件大小否则 0 字节读入返回 0 假成功（须先 stat 再 vmalloc 按 size 读）。

### B3. 源文件内嵌真实 NUL 字节（编译警告 "null character(s) preserved in literal"）
- **位置**：`agent/ai/policy/ai_user_policy.c` 字节偏移 4262：`*hash = '<0x00>';` 应为 `'\0'`
- **【处置 09-29 晚】已修复**（一行改写）。

### B4. executor.h 顶部注释与实现矛盾（陈旧的"无交互确认"口径）

### B5. KUnit 测试套件未编入发行内核
